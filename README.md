# 无服务器 CRDT 协作文档编辑器

这是一个零构建、零第三方运行时依赖的浏览器原型，只使用 `IndexedDB`、`BroadcastChannel` 和 `Web Worker`。

## 启动

```bash
npm start
```

然后在同一个浏览器、同一个源下打开至少 4 个标签页：

```text
http://127.0.0.1:5173/
```

首次进入为空文档，点击“写入 1 万字样例”会生成约 1.24 万字、100 个因果链式操作。也可以直接输入并手动编辑到 1 万字以上。

## 验收步骤

1. 打开 4 个标签页，点击“写入 1 万字样例”，等待时间轴出现 100 个操作。
2. 在 4 个标签页中分别定位到同一段落，持续并发输入、退格、选中删除、`Ctrl/Cmd+B` 加粗 5 分钟。
3. 编辑期间观察编辑区输入响应；冲突合并、快照生成、回放索引都在 Worker 内执行，主线程只做一帧一次的 DOM 渲染。
4. 刷新任意标签页、关闭后重新打开，Worker 会先从 IndexedDB 完整恢复操作日志，再重建当前文档和时间轴。
5. 断开网络后继续编辑，操作仍先写入本地 IndexedDB；恢复网络、标签页重新可见或点击“重新请求同步”后，通过 BroadcastChannel 补齐缺失操作。
6. 点击“查看历史”，拖动时间轴或使用暂停、`−1`、`+1`、首帧、播放速度控件，可跳转到任意历史点。

## CRDT 设计

- 每个字符是一个带墓碑的 RGA 节点，身份为 `(lamport, seq, clientId, part)`。
- 插入操作引用左侧字符或根节点；同一位置的并发插入按 Lamport、clientId 等字段全序排列。
- 删除是永久 tombstone，不物理删除节点，因此并发删除与插入不会丢字符。
- 加粗是每个字符上的 LWW 寄存器，依据操作 Lamport 和 clientId 确定确定性胜者。
- 乱序到达的操作先放入 Worker 的 pending 队列，依赖操作到达后自动冲刷。
- 每个操作带 `vclock`、Lamport、clientId、seq、opId，时间轴按因果顺序排序。

## 持久化与通信

- 本地编辑：先在 IndexedDB 事务中写入操作，事务成功后才更新 Worker 状态并通过 BroadcastChannel 广播。
- 远端操作：收到后先写入本标签页 IndexedDB，再合并到内存 CRDT；不二次转发，避免消息风暴。
- 新标签页、刷新、重新可见和网络恢复时发送 hello；其他标签页根据向量时钟只回复缺失操作。
- 操作日志不做压缩，因此当前实现优先保证可完整恢复和可回放。

## 回放

- `ReplayEngine` 在 Worker 中按因果顺序维护操作数组。
- 每 250 个操作保存一个不可变 checkpoint。
- 任意跳转从最近 checkpoint 重建，最多顺序应用 249 个操作。
- checkpoint 恢复使用干净状态和 `applied` 集合，同一个操作不会在一次重建中重复应用。

## 测试

```bash
npm test
```

测试覆盖：

- 4 个副本同段落并发插入、删除、加粗后的文本和加粗状态一致。
- 操作日志以 8 种不同乱序投递后结果一致。
- 乱序子操作先 pending、父操作到达后自动应用，且重复投递幂等。
- 时间轴前向、后向、跳转和 checkpoint 恢复正确。

## 浏览器限制

- 4 个标签页必须同源；`file://` 对 Worker 和模块支持不一致，请使用 HTTP 服务。
- BroadcastChannel 是同源同浏览器内通信，不跨浏览器或跨设备。
- 断网不会影响同源 BroadcastChannel；“断网再恢复”场景还会通过在线事件和可见性事件重新执行缺失同步。
