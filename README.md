# 无服务器协作文档编辑器

纯前端、零依赖、零服务器的多标签页协作文档编辑器。所有协作只发生在同一台机器的浏览器标签页之间：

- **CRDT（简化版 RGA，字符级）** 保证并发收敛，无中心服务器、无锁
- **BroadcastChannel** 是标签页之间唯一的通信通道
- **IndexedDB** 是唯一持久化存储：每个操作**先写库、再广播、再合并**
- **Web Worker** 承担全部重计算（因果缓冲、冲突合并、时间轴快照索引、全文遍历）
- **因果向量时钟**记录每次操作的 happens-before 关系，乱序/重复/迟到消息均可正确处理

## 运行

```bash
# 任意静态服务器即可（Worker 为 ES Module，需要 http(s) 协议）
npm start                 # 等同 python3 -m http.server 8123
# 然后用浏览器打开 http://localhost:8123 ，再复制到 4 个标签页
```

首次打开会自动播种一篇 **1.1 万字以上**的长文档（播种内容本身也是可回放的操作日志）。

## 验收操作

1. 打开 4 个标签页，滚动到不同段落，同时输入、删除、`Ctrl+B` 加粗，持续约 5 分钟。
2. 顶栏实时显示字符数、操作数、在线标签页数；左下角显示主线程 FPS（并发编辑时应保持 60fps）。
3. 四个标签页的最终文本与加粗区间一致；不会出现重复或丢失字符（`npm test` 以 4 副本乱序+重复投递验证）。
4. 刷新 / 关闭任意标签页重开：Worker 从 IndexedDB 按规范序重放全部操作，文档与日志完整恢复。
5. 点「⏱ 回放历史」：拖动时间轴可跳到任意历史点，支持暂停、单步（⏮/⏭）、1×/4×/16×/64× 播放。
6. 「▶ 自动编辑」可在单标签页内模拟持续并发写入，便于观察回放与 FPS。
7. 断网（或标签页长时间休眠）恢复后，下一次 hello 握手会按向量时钟差异自动补传缺失操作。

## 目录结构

```
index.html        编辑器 / 工具栏 / 时间轴 UI
style.css
js/crdt.js        RGA CRDT 核心：字符节点、墓碑、加粗标记、向量时钟、快照
js/idb.js         IndexedDB Promise 封装（ops / meta 两个对象仓）
js/seed.js        首启播种的一万字长文档（本身就是历史操作）
js/worker.js      Worker：持久化、广播、因果缓冲、冲突合并、时间轴回放
js/app.js         主线程：输入差分 → CRDT 意图、DOM 渲染、光标、回放控件
test/             Node 收敛测试 + 多标签页集成测试（内存 IDB/Channel 垫片）
```

## 关键设计

### 操作模型

所有操作都是不可变消息，字段：`kind`（`ins`/`del`/`bold`/`unbold`）、`site`、`seq`、`lamp`、`vclock`、载荷、`ts`。

- `ins`：在锚点字符 `after` 之后插入一串字符，每个字符的全局 id 为 `lamport.site.seq.batchIndex`
- `del`：把目标字符写入墓碑集合（幂等、可交换）
- `bold`：生成新 mark id，挂到目标字符的 mark 集合
- `unbold`：把目标字符当前生效的 mark 写入停用集合

### 并发收敛

- 同一锚点的并发插入按 RGA 规则比较字符 id（lamport → site → seq），与消息到达顺序无关
- 插入锚定在**后来被删除**的字符上时，遍历跳过墓碑节点但不跳过其子树，存活子字符被提升显示——避免“并发插入 + 删除”丢字符
- 删除与加粗都是集合状态，重复应用无副作用

### 因果顺序

每个操作携带“依赖向量时钟”：只有接收方向量时钟覆盖操作依赖时才合并，否则进入因果缓冲。
冲刷缓冲时**每轮找任意一个就绪操作应用**（不能按 lamport 排序冲刷，否则未就绪操作会挡住其他站点的就绪操作）；合并位置由 RGA 保证顺序无关收敛。

### 先写库再广播

本地/远程操作都遵循：IndexedDB 事务完成 → 合并到内存文档 → 本地才广播（远程则无需再广播）。任何被对端见过的内容必然已在本机持久化。

### 时间轴回放

- IndexedDB 中的操作按规范序（lamport 升序、site、seq）排序，所有标签页得到同一条线性历史
- Worker 维护**独立的临时文档**从空文档逐操作应用；`Doc.applied` 集合保证同一操作不会被应用两次，暂停/单步/跳转均不重复
- 每 500 个操作存一份结构化快照，向后跳转时从最近快照恢复再补齐，删除全部快照仍可完整重放

### 线程模型

主线程只做：纯文本与上一帧输入做前后缀差分 → 翻译为删除/插入意图；接收 Worker 的渲染状态做 DOM 增量重建与光标恢复。合并、快照、遍历（1 万节点线性 DFS）全部在 Worker，渲染状态每帧最多下发一次。
